# Deep Plan: UX-оболочка как у @leomatchbot

**Дата:** 2026-08-14
**Источник:** разбор @leomatchbot / Дайвинчик как generic UI/UX-референса; текущий код `src/`; PRD §4, §6, §8; родительский MVP-план `.temp/code-davinci-mvp/deep-plan.md`
**Статус:** утверждён (Q1=A, Q2=C, Q3=A, Q4=A, после confirm — дом) и реализован. Remote-миграция и деплой — только по отдельной просьбе.
**Скоуп:** оболочка взаимодействия (клавиатуры, навигация, короткие экраны, копирайт хрома). Продуктовая петля (свайп кода, мэтч, дайджест) не переписывается.

Референс разобран по публичным гайдам и парсеру реальных сообщений Leo (`daivinchik-assist`: формат карточки, заголовок лайка, текст мэтча, исходящие `❤️`/`👎` как текст). Живой бот в этой сессии не проходили.

MVP-план не перезаписывать. Это отдельная задача поверх уже собранных срезов 02–06.

## 1. Постановка задачи

Продуктовая петля уже есть: онбординг → карточка со сниппетом → лайк/скип → инбокс → мэтч. Telegram-оболочка чужая: команды вместо нижнего меню, Like под длинным `<pre>`, пустые состояния без следующего действия, `/start` после регистрации не является домом.

@leomatchbot — дефолтная ментальная модель такого бота в Telegram. Нужно взять **оболочку** Leo, не дейтинг-продукт.

Главный продуктовый аргумент именно для нас: карточка code-davinci **выше**, чем у Leo (сниппет до 1500 символов). Reply-клавиатура остаётся на большом пальце; inline Like внизу сообщения требует скролла через код.

## 2. Текущее поведение

Команды + inline. `ReplyKeyboardMarkup` нигде нет.

| Поверхность | Сейчас |
|---|---|
| Вход | `/start` → онбординг или своя карточка. Главного меню нет. |
| Навигация | `setMyCommands`: start, feed, profile, filters, language, delete, cancel. `/filters`, `/language`, `/delete` — заглушки. `/matches` есть в срезе 05, **не подключён** в `bot.ts`. |
| Онбординг | Один вопрос за шаг. Выборы — inline. Превью Confirm / Start over. После confirm — **первая карточка ленты**, не меню. |
| Лента | HTML, первый сниппет, имя, возраст, языки, город/дистанция, био. Inline `👍 Like` / `👎 Skip`. Каждый свайп — новое сообщение. Старые inline остаются живыми. Empty — тупик. |
| Профиль | Своя карточка + чипы: Likes(n), имя/год/пол/био/локация/сниппеты. Поэлементный edit через conversation. |
| Лайки | Дайджест ≤1/24ч + inline «кто лайкнул». Инбокс — те же карточки без фото и без username. |
| Мэтч | Мгновенный reveal текстом (`sendMessage`, без фото). Pending-username работает. |
| Пауза | `is_active` есть (403 / блок бота). Пользователь сам скрыться не может. |

Идентичность, которую нельзя ломать (PRD §4, §8): в ленте нет фото; нет дейтинг-фильтров; нет чата внутри бота; нет Mini App.

## 3. Целевое поведение

Тот же продукт. Chrome как у Leo:

1. После готового профиля пользователь почти не печатает `/команды`.
2. На каждом экране 2–4 большие кнопки снизу (reply keyboard).
3. Кнопки пронумерованы; тап и ввод `1`/`2`/`3`/`4` эквивалентны.
4. Своя карточка показывается **так же, как чужая**, с рамкой «так выглядит твоя анкета».
5. Свайп идёт с нижней клавиатуры и относится к **последней показанной** карточке.
6. Пустой экран, мэтч, ошибка всегда оставляют клавиатуру.
7. `/feed`, `/profile`, `/start`, `/cancel` остаются алиасами.
8. Фото в ленте не появляются. `💌`, репорт, буст, «кого ищу» — не появляются.

## 8. Референс Leo (что считаем каноном оболочки)

Не клонировать продукт. Клонировать эти экраны и принципы.

| Экран | Клавиатура | Копирайт-якорь |
|---|---|---|
| Дом | `1. Смотреть анкеты` / `2. Моя анкета` / `3. Я больше не хочу никого искать` | почти без текста; своя карточка сверху |
| Лента | `❤️` `👎` `💤` (без `💌`) | только карточка |
| Свой профиль | `1. Смотреть анкеты` / `2. Заполнить заново` / `3. Сниппеты` / `4. Текст` | `Так выглядит твоя анкета:` |
| Входящий лайк | та же свайп-клавиатура | `Кому-то понравилась твоя анкета` |
| Мэтч | клавиатура дома | коротко + `t.me/<username>` |
| Пауза | `1. Смотреть анкеты` | профиль скрыт |

Формат карточки Leo (с живых сообщений): `Имя, 24, Москва` или `Имя, 24, 📍3 км – текст`.  
У нас карточка остаётся HTML со сниппетом. Меняется **рамка и кнопки**, не содержимое кода.

Дополнительно в наше меню (не у Leo, но уже есть в продукте): пункт «Лайки» и пункт «Мэтчи». Иначе инбокс и список мэтчей снова прячутся в команды.

Предлагаемый дом (RU):

```
1. Смотреть анкеты
2. Моя анкета
3. Лайки
4. Мэтчи
```

Пауза — не на первом ряду (как у Leo пункт 3), а в профиле или вторым экраном «ещё», чтобы дом не раздувать. Дефолт: пауза на экране профиля, не на доме.

EN — те же слоты, короткие глаголы (`Browse` / `My card` / `Likes` / `Matches`).

## 10. UX-состояния

- **Онбординг.** Те же шаги. Язык / пол / скип / confirm — reply. Язык сниппета — inline. `/cancel` и чужая `/команда` — как сейчас (`halt`). Текст кнопки другого экрана на шаге имени — re-prompt, не запись.
- **Дом.** Своя карточка (как в ленте, все сниппеты) + строка-рамка + клавиатура дома. `/start` при готовом профиле ведёт сюда.
- **Лента.** Карточка кандидата + клавиатура свайпа. `❤️` / `👎` пишут like/skip по `last_card_user_id`, затем следующая. `💤` → дом.
- **Инбокс.** Та же клавиатура, `browse_mode=inbox`. Пусто → дом или «пока никого» + дом-клавиатура.
- **Пустая лента.** Одна строка + клавиатура дома (не тупик).
- **Мэтч.** Одно короткое сообщение + ссылка + клавиатура дома. Pending-username без изменения правил.
- **Пауза (Q3=A).** `is_active=0`, не показываемся в чужих лентах. Клавиатура «вернуться». Любой апдейт сейчас ставит `is_active=1` в upsert — **это сломать нельзя молча**: пауза требует, чтобы upsert не реактивировал, пока пользователь сам не нажал «смотреть». Иначе пауза бесполезна. См. §12 шаг 8.
- **Дайджест.** Заголовок в духе Leo + кнопка/пункт «показать». Можно оставить inline «Показать» как дополнительный вход; нижняя клавиатура уже содержит «Лайки».

## 11. Потоки данных / state mapping

### 11.1 Экраны и клавиатуры

Один хелпер, без стейт-машины:

```
homeKeyboard(locale)
browseKeyboard(locale)      -- ❤️ / 👎 / 💤  (+ номера)
profileKeyboard(locale)     -- смотреть / заново / сниппеты / текст / пауза
pausedKeyboard(locale)
onboardingLang|Gender|Skip|Preview(locale)
```

Матч входа: точный текст текущей локали **или** ведущая цифра `^[1-4]$`. Команды `/feed` и т.д. зовут те же функции, что и пункты меню.

### 11.2 last_card (только Q1=A)

```
users.last_card_user_id INTEGER NULL
users.browse_mode TEXT NULL          -- 'feed' | 'inbox'
```

Пишем оба поля в том же запросе, что и показ карточки. Чистим: дом, пауза, empty, удаление.

`❤️` без `last_card_user_id` → «сначала открой анкеты», дом-клавиатура. Не падать.

Свайп: like/skip как сейчас (`ON CONFLICT`, событие только на insert, `processNewLike`). Затем следующая карточка из того же `browse_mode`.

### 11.3 Текст vs conversations

Порядок middleware не менять: private → upsert → pending-reveal → conversations → хендлеры.

Внутри `wait()` онбординга/edit:

- `/команда` — как сейчас, `halt`;
- текст, который равен кнопке **другого** экрана (лента/дом), пока ждём имя/био/сниппет — **не сохранять**, re-prompt;
- текст кнопки **текущего** шага (RU/EN, скип, confirm) — это ответ шага.

Не вешать глобальный `hears('❤️')` выше conversations так, чтобы он перехватывал апдейт у активного диалога.

### 11.4 Пауза vs upsert

Сейчас user-middleware на любом апдейте делает `is_active=1`. Для паузы:

- выделить «пользователь явно скрылся» (`is_active=0` **и** не 403);
- upsert **не** поднимает `is_active`, пока не пришла команда/кнопка «смотреть анкеты» / явный resume.

403 от send по-прежнему `is_active=0`. Resume после unblock — только явное действие, либо оставить реактивацию после unblock как сейчас (пользователь сам написал боту). Дефолт: любое **явное** нажатие «смотреть» включает; простое сообщение без кнопки на паузе не публикует анкету обратно, а показывает paused-клавиатуру.

Фейки и `is_active` не смешивать.

### 11.5 Команды = алиасы

| Команда | Куда |
|---|---|
| `/start` готовый | дом |
| `/start` онбординг | как сейчас |
| `/feed` | лента |
| `/profile` | свой экран |
| `/matches` | список мэтчей (подключить хендлер) |
| `/cancel` | выход из диалога → дом или онбординг |
| `/filters` `/language` `/delete` | заглушка + клавиатура дома |

`setMyCommands` не чистим.

## 12. Шаги реализации

Только после утверждения плана. Один вертикальный срез «оболочка», если не попросят декомпозицию (см. §16).

1. Словари: подписи кнопок, номера, хром, мэтч, лайки, пауза, empty. Карточка кода — без смены смысла.
2. `src/keyboards.ts`: разметка + `matchMenuAction(text, locale) → action | null`.
3. Миграция Q1=A: две колонки. `drizzle-kit generate` → apply local (remote — только по просьбе).
4. Показ карточки ленты/инбокса всегда пишет `last_card_*` и вешает `browseKeyboard`.
5. Text-handlers в `bot.ts` после conversations: дом / свайп / профиль / пауза. Команды зовут те же функции.
6. Онбординг: reply на бинарных шагах; после confirm — дом (если не выберут «сразу лента»).
7. Профиль: убрать сетку чипов с первого экрана; пункты меню → существующий `editProfile`.
8. Пауза: не реактивировать в upsert без явного resume. Проверить 403-путь.
9. Мэтч и дайджест: короткий текст; после сообщения — клавиатура дома. Подключить `/matches`.
10. Empty / ошибка / «закончи профиль» — всегда с клавиатурой.
11. `pnpm typecheck`. Ручной проход в Telegram (без деплоя, пока не попросят).

## 13. Проверка

- Новый пользователь после `/start` не обязан печатать слэш.
- На длинном сниппете Like доступен снизу экрана, без скролла сообщения.
- `1` на доме = смотреть анкеты; `1` на свайпе не путается (на свайпе первый слот — `❤️`, лучше нумеровать `1 ❤️` `2 👎` `3 💤`).
- `/feed` и `/profile` работают как раньше по смыслу.
- В середине имени `❤️` не записывается как имя.
- Пустая лента не тупик.
- Лайк/скип/мэтч/pending-username/дайджест 1/24ч — те же правила.
- Пауза: не появляемся у других; resume только с кнопки.
- Старый inline Like в истории может ещё нажаться — принимаем; новые карточки без inline.
- `pnpm typecheck`.

Автотесты не пишем.

## 14. Риски и краевые случаи

| Риск | Обработка |
|---|---|
| Reply-текст съедает `wait()` онбординга | allowlist текущего шага; чужие кнопки = re-prompt |
| Глобальный `hears` перехватывает диалог | хендлеры только если нет active conversation |
| Протухший `last_card_user_id` | чистить на доме/паузе/empty; нет id → подсказка, не like |
| Смена локали меняет подписи кнопок | матч по словарю **текущей** локали + цифры + slash |
| Upsert снимает паузу | §11.4, обязательная проверка |
| Две локали, пользователь жмёт старую EN-кнопку сидя на RU | не матчится → «нажми кнопку внизу» |
| Гонки webhook как в MVP | не трогаем like/match/digest |
| Scope creep в фильтры/💌/репорт | стоп, это Q4/Q7 / P1 |
